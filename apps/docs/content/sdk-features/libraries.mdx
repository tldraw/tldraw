In tldraw, a library is a named list of items, and each item is a saved copy of some shapes. People save shapes from the canvas into a library, then place copies of them on any canvas that shows that library. Your app can also provide libraries of its own, such as starter shapes bundled as a [pack](#Packs) or a shared library served from your backend through a [source](#Library-sources).

The `@tldraw/libraries` package works at two levels. [LibrariesPanel](?) is a panel you render in front of the canvas: it lists the libraries, saves the selection, and places items by click or drag. Everything it reads and writes goes through a [LibrarySource](?), an interface you can implement for any backend. The panel's pieces and hooks are exported too, so you can replace any of them or lay out your own UI.

Libraries are a licensed feature. They run in development without a key. In production they need a tldraw license that includes libraries, or one that includes collaboration.

## Setup

Install the libraries package alongside `tldraw`:

```bash
npm install @tldraw/libraries
```

You need one source, which holds the libraries, and the UI that reads it. The UI is four components, each in a tldraw [component slot](/sdk-features/ui-components#Component-slots): the panel, a button that opens it, the **Add to library** item in the context menu, and a group in the [command palette](/sdk-features/ui-components#Command-palette).

```tsx
import {
	AddToLibraryMenuItem,
	CommandPaletteLibrariesGroup,
	InMemoryLibrarySource,
	LibrariesPanel,
	librariesPanelOpen,
	LibrariesQuickActions,
} from '@tldraw/libraries'
import {
	DefaultCommandPalette,
	DefaultCommandPaletteContent,
	DefaultContextMenu,
	DefaultContextMenuContent,
	TLComponents,
	Tldraw,
} from 'tldraw'
import '@tldraw/libraries/libraries.css'
import 'tldraw/tldraw.css'

// In production, a tldraw license key that includes libraries. Not needed in development.
const YOUR_LICENSE_KEY = undefined

// Where libraries come from. This one keeps them in memory, so they're gone on reload.
const source = new InMemoryLibrarySource()

const components: TLComponents = {
	InFrontOfTheCanvas: () => <LibrariesPanel source={source} />,
	QuickActions: LibrariesQuickActions,
	ContextMenu: (props) => (
		<DefaultContextMenu {...props}>
			<AddToLibraryMenuItem source={source} />
			<DefaultContextMenuContent />
		</DefaultContextMenu>
	),
	CommandPalette: (props) => (
		<DefaultCommandPalette {...props}>
			<CommandPaletteLibrariesGroup source={source} />
			<DefaultCommandPaletteContent />
		</DefaultCommandPalette>
	),
}

export default function App() {
	return (
		<div style={{ position: 'fixed', inset: 0 }}>
			<Tldraw
				licenseKey={YOUR_LICENSE_KEY}
				components={components}
				onMount={(editor) => {
					librariesPanelOpen.set(editor, true)
				}}
			/>
		</div>
	)
}
```

Mount the panel through the `InFrontOfTheCanvas` component slot, and import `libraries.css` alongside `tldraw.css`. Every piece of UI takes the same `source`, so they all show the same libraries.

`LibrariesQuickActions` replaces the `QuickActions` slot with tldraw's quick actions plus a button that opens and closes the panel. To keep the button but choose the quick actions yourself, put `LibrariesToolbarButton` inside your own `DefaultQuickActions`. To put the toggle somewhere else entirely, render `LibrariesPanelButton`.

The panel shows while the `librariesPanelOpen` [editor atom](/sdk-features/signals#Atoms) is set. `toggleLibrariesPanel(editor)` flips it. The atom is scoped per editor, so two editors on one page each have their own panel.

<Callout type="warning">
	Without a license key that includes libraries, `LibrariesPanel`, `LibrariesPanelButton`, the
	button `LibrariesQuickActions` adds, `AddToLibraryMenuItem` and `CommandPaletteLibrariesGroup`
	render nothing in production. The feature is fully enabled in development, so a missing key shows
	up as missing UI after you deploy. See [License key](/sdk-features/license-key).
</Callout>

The license gates the UI, not the data. A document that holds libraries loads, migrates and saves without a key. To gate UI of your own the same way, read [useLibrariesEnabled](?).

## Saving and placing items

To save shapes, select them and click the + tile at the end of a library, or right-click and pick a library under **Add to library**. The submenu also offers **New library**, which creates one and saves the selection into it with its name ready to edit. With the panel open, it scrolls to the library that was saved to. With the panel closed, a toast confirms the save and can open the panel there.

An item saves the selected shapes as they'd be copied, with their bindings and assets. Several shapes keep their layout without being grouped. To place them as one shape instead, pass `wrapInGroup` as `prepareItemContent`:

```tsx
import { LibrariesPanel, wrapInGroup } from '@tldraw/libraries'
import { TLComponents } from 'tldraw'

const components: TLComponents = {
	InFrontOfTheCanvas: () => <LibrariesPanel source={source} prepareItemContent={wrapInGroup} />,
}
```

`AddToLibraryMenuItem` and `CommandPaletteLibrariesGroup` take the same prop. A `PrepareItemContent` is any `(content, editor) => TLContent` function. It runs while the shapes are still on the page, so it can measure them, and it doesn't change the shapes on the page.

Placing works like [pasting](/sdk-features/clipboard#Placing-content).

| Input                       | Result                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Click an item               | Places a copy in the middle of the viewport, selected. Switches to the select tool if another tool is active.                                     |
| Drag an item out            | Places a copy under the pointer. It follows the pointer until you release it.                                                                     |
| Right-click or long-press   | Opens the item's menu: insert, details, rename, move, copy, and delete, as the source allows.                                                     |
| Pick an item in the palette | Each library with named items is an **Insert from** submenu. Typing a query lists matching items directly. Picking one places it as a click does. |

A placed item lands inside the deepest shape at that point that accepts it, such as a frame. A drag starts once the pointer leaves the panel and has moved past the editor's [`uiDragDistanceSquared`](/sdk-features/options#Drag-detection) option (`uiCoarseDragDistanceSquared` for touch and pen).

On a phone, below the breakpoint where tldraw's toolbar switches to its mobile layout, the panel is a sheet along the bottom of the screen. Tapping an item places it and closes the sheet. Items can't be dragged out of the sheet.

### Saving and placing from code

[saveShapesToLibrary](?) saves shapes the way the + tile does, with a thumbnail rendered in light and dark mode. [placeLibraryItem](?) places an item the way a click does.

```tsx
import { placeLibraryItem, saveShapesToLibrary } from '@tldraw/libraries'

const item = await saveShapesToLibrary(editor, source, libraryId, editor.getSelectedShapeIds(), {
	name: 'Card',
})

await placeLibraryItem(editor, source, item.id, { point: { x: 400, y: 300 }, select: false })
```

Both reject with the source's error when the write or the load fails. `placeLibraryItem` also rejects with `LibraryNotFoundError` when the source doesn't list the item. Without `point`, the item lands in the middle of the viewport.

To change how the panel places items, pass a `LibraryItemPlacer` as `placeItem`. It receives the item, its content, the drop point and whether it was clicked or dragged, and returns the ids of the root shapes it placed. Call `defaultPlaceLibraryItem` to keep the usual placing and adjust the result:

```tsx
import { defaultPlaceLibraryItem, LibrariesPanel, LibraryItemPlacer } from '@tldraw/libraries'
import { TLComponents } from 'tldraw'

const placeMapsBehind: LibraryItemPlacer = (editor, placement) => {
	const ids = defaultPlaceLibraryItem(editor, placement)
	if (placement.item.meta.kind === 'map') editor.sendToBack(ids)
	return ids
}

const components: TLComponents = {
	InFrontOfTheCanvas: () => <LibrariesPanel source={source} placeItem={placeMapsBehind} />,
}
```

The panel makes an [undo stopping point](/sdk-features/history#Marks-and-stopping-points) before the placer runs, so a placement undoes in one step. A drag hands the placed shapes to the select tool, which moves them until the pointer is released. Anything that should happen on drop, like snapping to a grid, belongs in the shape util's [`onTranslateEnd`](/sdk-features/shapes#Lifecycle-hooks).

## Searching

The panel has a search field at the top. A query matches names, ignoring case. A library whose name contains it shows with all its items, and any other library shows only the items whose names contain it. Libraries with neither are left out. Escape or the ✕ clears the query.

Search covers the libraries the document shows. The command palette group searches the same names: while the palette has a query, it lists the best matching items, and picking one places it as clicking its tile does.

When a source fetches items separately through `loadItems`, the panel loads every library's items to search them. To search fewer, implement `mayHaveItemsMatching(libraryId, query)`. It answers without the items, for example from a list of item names the source already has, and the panel loads and searches only libraries whose name matches or for which it returns `true`. The `query` it receives is trimmed and lowercased.

## Library sources

The libraries UI only talks to the `LibrarySource` interface. The package ships three sources, and you can write your own.

| Source                   | Keeps libraries                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------- |
| `InMemoryLibrarySource`  | In memory. For tests, prototypes, read-only packs, and as a reference implementation. |
| `BoardLibrarySource`     | In the document itself, as records next to its shapes.                                |
| `CompositeLibrarySource` | Nowhere itself. It combines several sources, each under an owner.                     |

### InMemoryLibrarySource

[InMemoryLibrarySource](?) holds its libraries in a [tldraw store](/sdk-features/store), which validates them. Pass `initial` to start with data. It checks the data up front and throws on duplicate ids, an item without content, a library inside a missing parent, and similar mistakes.

```tsx
import {
	InMemoryLibrarySource,
	LibraryItemRecordType,
	LibraryRecordType,
	TLLibraryItemContent,
} from '@tldraw/libraries'

const library = LibraryRecordType.create({ name: 'Wireframes' })
const button = LibraryItemRecordType.create({ libraryId: library.id, name: 'Button' })
// The button's shapes, copied from the current page
const content = editor.getContentFromCurrentPage(editor.getSelectedShapeIds())!
const buttonContent: TLLibraryItemContent = { formatVersion: 1, content }

const source = new InMemoryLibrarySource({
	initial: {
		libraries: [library],
		items: [button],
		contents: { [button.id]: buttonContent },
	},
	// Read-only: items can be placed, but nothing can be changed
	can: () => false,
})
```

`can` decides what the user may do, and defaults to allowing everything. See [Permissions](#Permissions). The source turns thumbnail blobs into object URLs. Call `dispose()` when you throw the source away to release them.

### Writing your own source

To keep libraries in your own backend, implement `LibrarySource`. The required members are a stable `id`, the reads `getLibraries`, `getItems` and `getItemContent`, the permission check `can`, and the writes `createLibrary`, `renameLibrary`, `deleteLibrary`, `addItem`, `updateItem` and `deleteItem`. Everything else is optional, and the UI hides what a source leaves out.

The getters are reactive. The panel reads them inside `useValue`, so a source that keeps its listing in an [atom](?) updates the UI whenever the atom changes. Writes are async, since most sources save to a server. A write resolves once its result is listed in the getters.

This source saves to `localStorage`:

```ts
import {
	LibraryItemRecordType,
	LibraryNotFoundError,
	LibraryRecordType,
	LibrarySource,
	parseLibraryItemContent,
	TLLibrary,
	TLLibraryId,
	TLLibraryItem,
	TLLibraryItemContent,
	TLLibraryItemId,
	TLLibraryItemPartial,
	TLLibraryThumbnail,
	TLNewLibraryItem,
	TLNewLibraryOptions,
} from '@tldraw/libraries'
import { atom, FileHelpers } from 'tldraw'

interface Saved {
	libraries: TLLibrary[]
	items: TLLibraryItem[]
	contents: Record<TLLibraryItemId, TLLibraryItemContent>
}

const KEY = 'my-libraries'

function load(): Saved {
	const saved = localStorage.getItem(KEY)
	return saved ? JSON.parse(saved) : { libraries: [], items: [], contents: {} }
}

export class LocalStorageLibrarySource implements LibrarySource {
	readonly id = 'local-storage'
	private readonly saved = atom<Saved>('saved libraries', load())

	getLibraries() {
		return this.saved.get().libraries
	}

	getItems(libraryId: TLLibraryId) {
		return this.saved.get().items.filter((item) => item.libraryId === libraryId)
	}

	async getItemContent(itemId: TLLibraryItemId) {
		const content = this.saved.get().contents[itemId]
		if (!content) throw new LibraryNotFoundError(itemId)
		return content
	}

	can() {
		return true
	}

	async createLibrary(name: string, options: TLNewLibraryOptions = {}) {
		const library = LibraryRecordType.create({ name, meta: options.meta ?? {} })
		this.write((s) => ({ ...s, libraries: [...s.libraries, library] }))
		return library
	}

	async renameLibrary(libraryId: TLLibraryId, name: string) {
		this.assertLibraryExists(libraryId)
		this.write((s) => ({
			...s,
			libraries: s.libraries.map((l) => (l.id === libraryId ? { ...l, name } : l)),
		}))
	}

	async deleteLibrary(libraryId: TLLibraryId) {
		this.assertLibraryExists(libraryId)
		this.write((s) => {
			const contents = { ...s.contents }
			for (const item of s.items) if (item.libraryId === libraryId) delete contents[item.id]
			return {
				libraries: s.libraries.filter((l) => l.id !== libraryId),
				items: s.items.filter((item) => item.libraryId !== libraryId),
				contents,
			}
		})
	}

	async addItem(libraryId: TLLibraryId, newItem: TLNewLibraryItem) {
		this.assertLibraryExists(libraryId)
		const thumbnail = newItem.thumbnail && (await toDataUrls(newItem.thumbnail))
		const item = LibraryItemRecordType.create({
			libraryId,
			createdAt: Date.now(),
			...(newItem.name === undefined ? {} : { name: newItem.name }),
			...(thumbnail === undefined ? {} : { thumbnail }),
			...(newItem.meta === undefined ? {} : { meta: newItem.meta }),
		})
		const content = parseLibraryItemContent(newItem.content)
		this.write((s) => ({
			...s,
			items: [...s.items, item],
			contents: { ...s.contents, [item.id]: content },
		}))
		return item
	}

	async updateItem(itemId: TLLibraryItemId, { name, meta }: TLLibraryItemPartial) {
		this.assertItemExists(itemId)
		this.write((s) => ({
			...s,
			items: s.items.map((item) =>
				item.id === itemId
					? {
							...item,
							...(name === undefined ? {} : { name }),
							...(meta === undefined ? {} : { meta: { ...item.meta, ...meta } }),
						}
					: item
			),
		}))
	}

	async deleteItem(itemId: TLLibraryItemId) {
		this.assertItemExists(itemId)
		this.write((s) => {
			const { [itemId]: _deleted, ...contents } = s.contents
			return { ...s, items: s.items.filter((item) => item.id !== itemId), contents }
		})
	}

	private assertLibraryExists(libraryId: TLLibraryId) {
		const exists = this.saved.get().libraries.some((l) => l.id === libraryId)
		if (!exists) throw new LibraryNotFoundError(libraryId)
	}

	private assertItemExists(itemId: TLLibraryItemId) {
		const exists = this.saved.get().items.some((item) => item.id === itemId)
		if (!exists) throw new LibraryNotFoundError(itemId)
	}

	private write(change: (saved: Saved) => Saved) {
		const next = change(this.saved.get())
		localStorage.setItem(KEY, JSON.stringify(next))
		this.saved.set(next)
	}
}

async function toDataUrls(thumbnail: TLLibraryThumbnail<Blob>): Promise<TLLibraryThumbnail> {
	if (thumbnail instanceof Blob) return FileHelpers.blobToDataUrl(thumbnail)
	const [light, dark] = await Promise.all([
		FileHelpers.blobToDataUrl(thumbnail.light),
		FileHelpers.blobToDataUrl(thumbnail.dark),
	])
	return { light, dark }
}
```

A few rules the UI relies on:

- Content is loaded separately from the listing. `getItems` returns listing entries only, and `getItemContent` loads an item's shapes when it's placed or copied, so showing a library never loads every item's shapes.
- `updateItem` merges `meta` key by key, the way `editor.updateShape` merges a shape's. A name can be changed but never removed or made blank.
- `deleteLibrary` deletes everything inside the library: its items, and any libraries nested in it.
- Throw the package's errors so the UI can tell failures apart. Throw `LibraryNotFoundError` for an id that doesn't exist, `LibraryPermissionError` for a write the user isn't allowed to make, and `LibraryNestingError` for a library that can't go where it was asked to. `getLibraryErrorReason(error)` maps an error to `'not-found'`, `'rejected'`, `'too-new'` or `'failed'`.

The optional members add capabilities:

| Member                                                                                              | Adds                                                                                          |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `addItems`                                                                                          | Saving several items in one write. Without it, they're added one at a time through `addItem`. |
| `moveItem`                                                                                          | **Move to** in the item menu.                                                                 |
| `copyLibrary`                                                                                       | Copying a library server-side. Without it, `copyLibrary` loads and re-adds every item.        |
| `getLibraryOwners`, `getDefaultOwnerId`, `getNewLibraryOwnerIds`                                    | Owners. See [Owners](#Owners).                                                                |
| `getLibraryPlacement`, `getAvailableLibraries`, `addLibraryToDocument`, `removeLibraryFromDocument` | Libraries shown per document. See [Libraries in documents](#Libraries-in-documents).          |
| `resolveThumbnail`                                                                                  | Thumbnail URLs sized for their tile. See [Thumbnails](#Thumbnails).                           |
| `getItemDetails`                                                                                    | A creator name and description in an item's details.                                          |
| `loadItems`, `isLoadingItems`                                                                       | Items fetched per library, when the panel is about to show them.                              |
| `getItemCount`, `getPreviewItems`, `mayHaveItemsMatching`                                           | Counts, previews and search hints for libraries whose items aren't fetched yet.               |

The [custom library source example](/examples/collaboration/libraries-local-storage) is a version of the source above that waits on every write, as if it saved to a server.

## Board libraries

[BoardLibrarySource](?) keeps libraries in the editor's own document, as records next to its shapes. They're saved, synced and copied wherever the document goes, so a document carries the libraries it uses.

The library record types aren't in the default schema. [Register `librarySchemaRecords` on the store](/sdk-features/store#Custom-record-types), then give the source the editor:

```tsx
import { BoardLibrarySource, LibrariesPanel, LibrariesQuickActions } from '@tldraw/libraries'
import { useMemo } from 'react'
import {
	createTLSchema,
	createTLStore,
	Editor,
	librarySchemaRecords,
	TLComponents,
	Tldraw,
	useEditor,
	useToasts,
	useTranslation,
} from 'tldraw'

const sources = new WeakMap<Editor, BoardLibrarySource>()

// One source per editor, made inside the editor's UI so it can report failed uploads in a toast
function useBoardLibraries() {
	const editor = useEditor()
	const toasts = useToasts()
	const msg = useTranslation()
	let source = sources.get(editor)
	if (!source) {
		source = new BoardLibrarySource(editor, { toasts, msg })
		sources.set(editor, source)
	}
	return source
}

const components: TLComponents = {
	InFrontOfTheCanvas: () => <LibrariesPanel source={useBoardLibraries()} />,
	QuickActions: LibrariesQuickActions,
}

export default function App() {
	const store = useMemo(
		() => createTLStore({ schema: createTLSchema({ records: librarySchemaRecords }) }),
		[]
	)
	return <Tldraw store={store} components={components} />
}
```

The source throws when it's created if the store doesn't register the three library record types: `library`, `library-item` and `library-item-content`.

An item's content is a record of its own, so listing a library never reads shapes. Its assets are the document's ordinary asset records: an item saved from the board shares the assets its shapes already use. Thumbnails are image assets too, uploaded through [the editor's asset store](/sdk-features/assets) the way a pasted image is. The item is listed immediately and shows a local preview while its thumbnail uploads. If the upload fails, the item is removed again. The failure shows in a toast when the source has both the `toasts` and `msg` options, and is only logged otherwise.

Board library writes don't go on the [undo stack](/sdk-features/history). Saving to a library isn't an edit to the canvas. While the editor is [read-only](/sdk-features/readonly), `can` refuses everything. The board doesn't track owners, so `createLibrary` with an `ownerId` throws `LibraryNotFoundError`.

With the `documentLibrary` option, the document gets one library of its own instead of any number. It's listed under the name you pass, which should be translated for the current user, and it can't be renamed or deleted. It's written into the document on the first save to it. Set `hideUntilSaved` to list it only once it exists, for example for a viewer who can't save to it.

```tsx
new BoardLibrarySource(editor, { documentLibrary: { name: 'This file' } })
```

To sync board libraries, register the same records on both ends of the connection, as you would for [comments](/sdk-features/commenting#Syncing-comments). Pass `records: librarySchemaRecords` to `useSync` on the client, and `createTLSchema({ records: librarySchemaRecords })` on the server. See [Collaboration](/sdk-features/collaboration).

## Owners, placements and permissions

### Owners

An owner is something a library can belong to, such as a user, a team or a workspace. A library names its owner in `ownerId`. The source decides what an owner is. A source that tracks owners lists them, in the order the UI should show them, with `getLibraryOwners()`. Each `TLLibraryOwner` has an `id`, a `name` and an optional `icon`.

[CompositeLibrarySource](?) builds one source from several, each under an owner. Each read and write goes to the part that holds the library or item, and a new library goes to the part of the owner it names.

```tsx
import { BoardIcon, CompositeLibrarySource, InMemoryLibrarySource } from '@tldraw/libraries'

const source = new CompositeLibrarySource({
	defaultOwnerId: 'personal',
	parts: [
		{
			owner: { id: 'board', name: 'This file', icon: <BoardIcon /> },
			source: new InMemoryLibrarySource({ id: 'board' }),
		},
		{
			owner: { id: 'personal', name: 'Private to you' },
			source: new InMemoryLibrarySource({ id: 'personal' }),
		},
		{
			owner: { id: 'packs', name: 'Packs' },
			source: new InMemoryLibrarySource({ id: 'packs', initial: packData, can: () => false }),
		},
	],
})
```

A part without an `owner` must list its own with `getLibraryOwners`, and its libraries keep the owners it gives them. Two parts can name the same owner to list their libraries together. Libraries created for that owner go to the first of them.

With owners, **Create library** in the panel's ⋯ menu offers each owner the user may create a library for. A library's menu offers **Copy to** each other owner. **Add to library** names a library's owner next to it when libraries from several owners, or two libraries with the same name, are listed. `getDefaultOwnerId` decides where a new library goes when the user doesn't pick, and `getNewLibraryOwnerIds` narrows which owners are offered for libraries created from this document.

Moving an item between parts copies it and deletes the original, so the item gets a new id. `moveItem` resolves to the id it ends up with.

### Libraries in documents

Some apps keep libraries outside documents, in workspaces, and let each document choose which ones it shows. A source like that answers `getLibraryPlacement(libraryId)` with why a library is shown:

| Placement    | Meaning                                                                    |
| ------------ | -------------------------------------------------------------------------- |
| `'housed'`   | Kept in the document itself, and goes wherever the document goes.          |
| `'added'`    | Kept elsewhere, such as in a workspace, and added to this document.        |
| `'default'`  | The user's own default library, shown in every document they open.         |
| `'document'` | The document's own library, which the panel lists first under "This file". |

With placements, the panel lists the user's default first, then a "This file" section that starts with the document's own library. Without them, it lists libraries in the order the source gives.

`getLibraries` returns only the libraries the document shows. `getAvailableLibraries` returns the rest the user could add, and `getItems` answers for those too, so they can be browsed before they're added. With both `getAvailableLibraries` and `addLibraryToDocument`, or with the panel's `getBrowseGroups` prop, the panel's ⋯ menu offers **Add library** and its footer offers **Add libraries**. Both open the **Browse libraries** dialog, which lists the libraries to add. The command palette offers the same dialog as **Browse more libraries**. With `removeLibraryFromDocument`, an `'added'` library's menu offers **Remove from file**. That leaves the library itself where it's kept, ready to add again. The panel doesn't offer to delete an `'added'` or `'default'` library from its menu.

`BoardLibrarySource` answers `'housed'` for its libraries, or `'document'` for its `documentLibrary`. `InMemoryLibrarySource` takes a `shownInDocument` option, a list of top-level library ids and their placements. Libraries left out of it are available to add. The [libraries in documents example](/examples/collaboration/libraries-documents) builds a source for this from a shared workspace source.

### Permissions

`can(action, target)` answers whether the current user may do something. The actions are `'createLibrary'`, `'renameLibrary'`, `'deleteLibrary'`, `'addItem'`, `'updateItem'`, `'deleteItem'`, `'addLibraryToDocument'` and `'removeLibraryFromDocument'`. The target says what it's asked about:

| Target        | Asks about                                                                        |
| ------------- | --------------------------------------------------------------------------------- |
| A library id  | That library. With `'createLibrary'`, whether a library may be created inside it. |
| `{ ownerId }` | That owner. For example, whether a library may be created for it.                 |
| Left out      | The source as a whole. For example, whether libraries may be created at all.      |

Using items has no action. Anything a source lists can be placed and copied. To keep a library from someone, don't list it to them.

The UI hides each control the source refuses: the + tile without `'addItem'`, rename and delete in the menus, **Create library**, and so on. `useLibraryCan(source, action, target)` reads the same answer in your own UI, and re-renders when it changes.

<Callout type="warning">
	`can` decides what the UI offers. It doesn't enforce anything on its own. A source that writes to
	a server should have the server check each write too, and throw `LibraryPermissionError` from the
	source when the server refuses.
</Callout>

## Nesting

A library can sit inside another. It names its parent in `parentId`, and sources list libraries flat. [getLibraryTree](?) arranges a flat list into trees of `TLLibraryTreeNode`, each with its `library`, `depth` and `children`. The panel shows nested libraries indented under their parent.

```ts
const parent = await source.createLibrary('Icons')
await source.createLibrary('Arrows', { parentId: parent.id })
```

A library and everything inside it share one owner. Pass an `ownerId` that differs from the parent's and the source throws `LibraryNestingError`. A nested library has no permissions or placement of its own: it has those of the library at the top of its tree, and it comes with that library when it's added to a document. Deleting or copying a library includes everything nested in it.

Nesting is optional for a source. One that ignores `parentId`, like the `localStorage` source above, lists every library at the top level, and a nested library copied into it arrives flat.

## Item content and versioning

An item's content is a `TLLibraryItemContent`: a `TLContent`, as `editor.getContentFromCurrentPage` returns it, in a versioned envelope.

```ts
const content = editor.getContentFromCurrentPage(editor.getSelectedShapeIds())
if (content) {
	await source.addItem(libraryId, {
		name: 'Card',
		content: { formatVersion: 1, content },
	})
}
```

`formatVersion` is `1`. Anything an item needs beyond its shapes will arrive as a new format version, so the way items are listed and stored doesn't change.

`parseLibraryItemContent(value)` validates content you load from outside, such as from a server or a file. It checks the envelope only. The shapes, bindings and assets inside it are [migrated](/sdk-features/persistence#Migrations) and validated against the editor's schema when the item is placed. If the content was written by a newer version of tldraw than the one running, it throws `LibraryItemContentTooNewError`. `BoardLibrarySource` also throws it from `getItemContent` when the shapes can't be migrated down, or use a shape or binding type the editor has no util for. Placing such an item shows a toast asking the user to reload.

An item's `version` is always `1`. Items aren't replaced: to change one, delete it and add it again. Every item carries a `meta` object the UI never reads, for your own fields.

## Thumbnails

A thumbnail is one image for every [color mode](/sdk-features/themes#Color-mode), or a light and a dark one. The `TLLibraryThumbnail<Src>` type covers both, where `Src` is whatever names the image: a `Blob` when adding an item, and a URL on a listed one.

`saveShapesToLibrary` renders a light and a dark PNG of the shapes, 512 pixels on the longest side. A single frame is rendered with its border and name. A source stores the images however it likes and lists URLs to them. `getThumbnailForColorMode(thumbnail, colorMode)` picks the image to show, and `mapThumbnail(thumbnail, convert)` converts each image while keeping the single-or-pair shape:

```ts
import { mapThumbnail, TLNewLibraryItem } from '@tldraw/libraries'

function toObjectUrls(newItem: TLNewLibraryItem) {
	return newItem.thumbnail && mapThumbnail(newItem.thumbnail, (blob) => URL.createObjectURL(blob))
}
```

Leave `thumbnail` out and the tile shows a placeholder.

Without `resolveThumbnail`, a tile shows the item's own `thumbnail` for the editor's color mode. A source that can serve images at different sizes, such as from an image CDN, implements `resolveThumbnail(item, context)` instead. The `TLLibraryThumbnailContext` has the `colorMode`, the tile's `width` in CSS pixels rounded up to a power of two, the screen's `dpr` capped at 2, and the browser's `networkEffectiveType`, such as `'4g'`, or `null`.

```ts
import {
	getThumbnailForColorMode,
	TLLibraryItem,
	TLLibraryThumbnailContext,
} from '@tldraw/libraries'

function resolveThumbnail(
	item: TLLibraryItem,
	{ colorMode, width, dpr }: TLLibraryThumbnailContext
) {
	if (!item.thumbnail) return null
	const url = new URL(getThumbnailForColorMode(item.thumbnail, colorMode))
	url.searchParams.set('width', String(width * dpr))
	return url.toString()
}
```

It's called for every item on screen, and again when the item or the context changes, so answer quickly. It can return a promise. A source that creates `blob:` URLs here owns them, and should keep one per item and size and revoke them when it's thrown away.

## Custom components

Every piece of the panel is a slot. Pass them through the `components` prop. Leave a slot unset to keep its default, or set it to `null` to hide it.

| Slot                   | Replaces                                                                  |
| ---------------------- | ------------------------------------------------------------------------- |
| `LibrariesPanelHeader` | The panel's title and ⋯ menu.                                             |
| `NoLibraries`          | What shows when there are no libraries.                                   |
| `LibrarySectionHeader` | A library's header: its name, which collapses it, and its menu.           |
| `LibraryMenu`          | A library's ⋯ menu.                                                       |
| `EmptyLibrary`         | What shows in a library with no items, when items can't be added to it.   |
| `ItemTile`             | An item's tile.                                                           |
| `ItemMenu`             | An item's ⋯ menu.                                                         |
| `AddSelectionTile`     | The + tile that saves the selection, shown when the source allows adding. |

Hiding the header, the + tile and both menus leaves a gallery that only places items:

```tsx
import { LibrariesComponents, LibrariesPanel } from '@tldraw/libraries'

const librariesComponents: LibrariesComponents = {
	LibrariesPanelHeader: null,
	AddSelectionTile: null,
	ItemMenu: null,
	LibraryMenu: null,
}

function Gallery() {
	return <LibrariesPanel source={source} components={librariesComponents} />
}
```

Each default is exported, so an override that only adds something can render the default with the same props. `ItemTile` and `ItemMenu` also receive the `item`, so they can show anything stored on it:

```tsx
import { ItemTile, ItemTileProps, LibrariesComponents, TLLibraryItem } from '@tldraw/libraries'

function CaptionedItemTile(props: ItemTileProps & { item: TLLibraryItem }) {
	return (
		<div className="captioned-tile">
			<ItemTile {...props} />
			{props.item.meta.isNew === true && <span className="badge">New</span>}
			<span className="caption">{props.item.name ?? 'Unnamed'}</span>
		</div>
	)
}

const librariesComponents: LibrariesComponents = { ItemTile: CaptionedItemTile }
```

A replacement tile must spread `buttonProps` onto the element that places the item, and render `menu`. A replacement `ItemMenu` must keep the `id` it's given, because right-clicking a tile opens the menu with that id.

To add actions to a menu, render the default menu with `LibraryMenuItem`s as children. The default actions stay in place:

```tsx
import { LibraryMenu, LibraryMenuItem, LibraryMenuProps, LibrarySource } from '@tldraw/libraries'
import { TLLibrary } from 'tldraw'

function LibraryMenuWithExport(
	props: LibraryMenuProps & { source: LibrarySource; library: TLLibrary }
) {
	const { source, library } = props
	return (
		<LibraryMenu {...props}>
			<LibraryMenuItem
				label="Export as JSON"
				onClick={() => {
					const items = source.getItems(library.id)
					navigator.clipboard.writeText(JSON.stringify({ library, items }))
				}}
			/>
		</LibraryMenu>
	)
}
```

The panel's own ⋯ menu takes extra items through `menuItems`, without replacing the header:

```tsx
<LibrariesPanel
	source={source}
	menuItems={<LibraryMenuItem label="Import…" onClick={openImport} />}
/>
```

A `LibrarySectionHeader` override that shows a rename input must end the rename with `onRenameComplete` or `onRenameCancel`, as the default input does. Otherwise the panel stays in rename mode. Render the default `LibrarySectionHeader` while `isRenaming` is true to keep its input.

### Sizing the panel

The panel's size and position follow CSS variables, set on the panel or any element around it.

| Variable                            | Default                                                     |
| ----------------------------------- | ----------------------------------------------------------- |
| `--tlui-libraries-panel-inset-top`  | `48px`, below the main menu.                                |
| `--tlui-libraries-panel-inset-side` | `8px`.                                                      |
| `--tlui-libraries-panel-max-height` | The canvas's height minus the insets, at most `720px`.      |
| `--tlui-libraries-columns`          | `3` tiles to a row.                                         |
| `--tlui-libraries-tile-width`       | `96px`. Override it with a rule on `.tlui-libraries-panel`. |

`side="right"` floats the panel on the right of the canvas instead of the left. Setting `--tlui-libraries-columns` to `1` and replacing `ItemTile` turns the grid into a list. See the [library list layout example](/examples/collaboration/libraries-list-layout).

### Building your own layout

The panel is built from hooks that are exported on their own, so you can lay libraries out any way you like.

| Hook                        | Returns                                                                         |
| --------------------------- | ------------------------------------------------------------------------------- |
| `useLibraries`              | The source's libraries.                                                         |
| `useLibraryItems`           | A library's items, optionally ordered by `'name'`, `'newest'` or `'source'`.    |
| `useLibraryThumbnailUrls`   | Each item's thumbnail URL, sized for a `width` or a measured `container`.       |
| `useLibraryItemDrag`        | A function that returns the props that place an item on click or drag.          |
| `useLibraryCan`             | Whether the source allows an action.                                            |
| `useLibraryCollapsed`       | Whether a library is collapsed, and a setter. Shared with the panel.            |
| `useSaveSelectionToLibrary` | Functions that save the selection to a library, or to a new one.                |
| `useLibraryActions`         | A library's rename, delete, remove and copy actions, as the source allows them. |
| `useLibraryItemActions`     | An item's rename, move, copy and delete actions.                                |
| `useLibraryItemOrder`       | The item ordering chosen in the panel's **Sort by** menu.                       |

```tsx
import {
	LibrarySource,
	useLibraries,
	useLibrariesEnabled,
	useLibraryItemDrag,
	useLibraryItems,
	useLibraryThumbnailUrls,
} from '@tldraw/libraries'
import { TLLibrary } from 'tldraw'

function Shelf({ source, library }: { source: LibrarySource; library: TLLibrary }) {
	const items = useLibraryItems(source, library.id, { ordering: 'name' })
	const thumbnails = useLibraryThumbnailUrls(source, items, { width: 56 })
	const getItemProps = useLibraryItemDrag(source)

	return (
		<section>
			<h3>{library.name}</h3>
			{items.map((item) => (
				<button key={item.id} aria-label={item.name ?? 'Unnamed'} {...getItemProps(item.id)}>
					{thumbnails[item.id] && <img src={thumbnails[item.id]} alt="" draggable={false} />}
				</button>
			))}
		</section>
	)
}

function Tray({ source }: { source: LibrarySource }) {
	const enabled = useLibrariesEnabled()
	const libraries = useLibraries(source)
	if (!enabled) return null
	return (
		<aside>
			{libraries.map((library) => (
				<Shelf key={library.id} source={source} library={library} />
			))}
		</aside>
	)
}
```

The hooks aren't license-gated, so gate a layout of your own with `useLibrariesEnabled`, as `Tray` does. `useLibrariesComponents()` returns the slots from the nearest `LibrariesComponentsProvider`, with the defaults filled in, for a layout that should honor the same overrides as the panel. The presentational pieces are exported too: `ItemGrid`, `ItemTile`, `ItemMenu`, `LibraryMenu`, `LibraryMenuItem`, `RenameInput` and `BoardIcon`.

The libraries UI reports `toggle-libraries-panel`, `place-library-item`, `open-browse-libraries` and `library-error` through tldraw's [`onUiEvent`](/sdk-features/ui-components#UI-events). Writes to a library aren't reported there. A host sees those through its source.

## Packs

A pack is a set of items shipped as data, such as starter shapes bundled with your app. A `LibraryPack` has a stable `id`, a `name`, a `version` and its `items`, each with its own `id`, `content`, and an optional `name`, `thumbnail` and `meta`. A pack's thumbnails are URLs, such as bundled assets or data URLs.

[parseLibraryPack](?) validates a pack loaded as data, including each item's content. [copyPack](?) copies it into a source as an ordinary library, which the user can then change like any other:

```ts
import { copyPack, parseLibraryPack } from '@tldraw/libraries'
import starterShapes from './starter-shapes.json'

const library = await copyPack(source, parseLibraryPack(starterShapes))
```

The copy takes the pack's name, numbered if the source already has a library by that name. Its `meta` records `packId` and `packVersion`, and `findPackCopy(libraries, packId)` finds a copy by them. If an item can't be added, the partial copy is deleted.

`addPackToDocument(source, packId, loadPack)` shows a pack in the document without making duplicate copies. It reuses a copy the document already shows, then one the user has available to add, and only calls `loadPack` to make a new copy when there's neither.

To offer packs in the **Browse libraries** dialog, pass `getBrowseGroups` to the panel. Each `LibraryBrowseGroup` is a labeled list of entries, listed after the libraries the source has available to add. With `getBrowseGroups`, the dialog is offered even by a source that doesn't add libraries to documents.

```tsx
import {
	addPackToDocument,
	findPackCopy,
	LibrariesPanel,
	LibraryBrowseGroup,
} from '@tldraw/libraries'

const getBrowseGroups = (): LibraryBrowseGroup[] => [
	{
		id: 'starter',
		label: 'Starter packs',
		entries: packs.map((pack) => {
			const copy = findPackCopy(source.getLibraries(), pack.id)
			return {
				id: pack.id,
				name: pack.name,
				itemCount: pack.items.length,
				previews: pack.items.slice(0, 5).map((item) => item.thumbnail),
				added: copy !== undefined,
				libraryId: copy?.id,
				canAdd: source.can('createLibrary'),
				add: () => addPackToDocument(source, pack.id, async () => pack),
			}
		}),
	},
]

function PacksPanel() {
	return <LibrariesPanel source={source} getBrowseGroups={getBrowseGroups} />
}
```

`getBrowseGroups` is called reactively, so it can read the source's getters. While "This file" holds no library besides the document's own, the panel offers up to three entries that aren't added yet and can be added. With the document's own library present, they show as suggestions below it. A source without placements has no "This file", so it gets no offers. `CommandPaletteLibrariesGroup` takes the same prop.
